# AGENTS.md — ui-astryx

Guidance for agents working in this app. The first part is Astryx's own agent guidance, generated by
`astryx init` (v0.7.16) and condensed from its docs (`astryx docs layout/*`, `principles`,
`is-my-code-good`). The second part is how this app applies it. `../ui/GUIDELINES.md` (the erpcraft UX
rules) still applies to every screen and wins where the two disagree.

## Layout, from `astryx docs layout`

- **Frame first.** AppShell + SideNav (the default nav). Each page is a `Layout`; tables fill their region,
  forms and records cap with `contentWidth` (640 for a form, 960–1000 for a record with a table).
- **Headers.** `LayoutHeader` holds the title and the primary action and stays pinned; `padding={4}`.
  With tabs under the title: `paddingBlockEnd={0}`. A back link sits above the title ("← Sales orders"),
  metadata on one line under it (status, number, who and when, separated by bullets).
- **One content line per region.** Header, body and footer share one padding token (4). The container
  owns padding; a Table or List owns its own inset, so its container gives up padding (`padding={0}`).
- **Structure.** Section is the default unit (no border); Card only for a self-contained widget or a hard
  boundary. No cards inside cards, no padded column of cards.
- **Rhythm.** Tight gaps bind (1–2 inside a field or item), generous gaps separate (6–8 between sections).
  Never one gap everywhere. FormLayout owns form spacing.
- **Type.** Body copy takes no props. Demote with `color="secondary"` or weight, not smaller text, and
  never with the disabled color. One lead per region, one primary action.
- **Density.** Compact for high-volume tables (lists, lines), balanced for most, spacious for settings.
  One control size per row, paired with the density (compact ↔ sm).

## How this app applies it

- Pages go through `src/components/page.tsx` (Layout, LayoutHeader with back link, title, metadata,
  actions, optional tabs, LayoutContent with one padding). Don't build headers elsewhere.
- Every table is `@erpcraft/grid` with the Astryx skin (`src/components/grid-skin.tsx`): lines
  (`lines-grid.tsx`), lists (`list-grid.tsx`, server mode) and everything read-only (`data-table.tsx`).
  Cell state is drawn from the grid's data attributes in `globals.css` (`.ag-*`), the one place CSS is
  allowed beyond tokens; keep it to state, borders and layout the grid's `style` cannot carry.
- Status is a StatusDot with its word (`status-badge.tsx`), never a colour alone.
- Decimals are strings end to end: `DecimalInput`, never NumberInput.
- Filtering is PowerSearch (`filter-bar.tsx`), one bar per list; the grid's own column filters are off.
- Checks before you call a change done: `tsc --noEmit`, `vite build`, `bun scripts/smoke.ts`,
  `bun scripts/grid-smoke.ts`, `bun scripts/invoice-smoke.ts`, `bun scripts/axe.ts`, then look at
  `bun scripts/screenshots.ts`.
